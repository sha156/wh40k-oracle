# 兵牌中文技能覆盖：补齐尝试与对账（2026-07-27）

用户反馈「危机火刃战斗服的技能还是英文」。本文是那次排查的落账：补了什么、
**补不到的是哪些、为什么补不到**，以及页面对补不到的部分怎么处理。

结论先行：**能补的已经补完，补不到的是源侧就没有，一个字都没有编。**

## 事实基线

技能中文正文全库**只有一个来源**：黑图书馆开放后端（`blackforum.czmakj.com`，
gameId=2）灌进 `unit_zh_detail.abilities_json`。`abilities` 表的 `text_zh` 列
4004 行非空但**含中文字符 0 行**——那一列装的是英文。所以「某单位技能为什么是英文」
只可能是黑图那边缺东西。

## 做了什么

1. **黑图缓存从 2026-07-08 刷到 2026-07-27**（`scripts/fetch_blacklibrary_details.py`）：
   源侧 list 1168 条 / 有英文名 1072 条，抓到 detail 1070 条。
   相比旧缓存：**新增 2 条记录**（CIAPHAS CAIN、HELL'S LAST）、
   **43 条技能正文被官方改写**、**0 条从空变成有**。
2. **补中文名桥**（`db_compile/blacklibrary.py`）：英文名只差单复数或头衔前缀时
   （`Hellflayer` vs `Hellflayers`、`Warsmith Kravek Morne` vs `Kravek Morne`、
   `scourges with Heavy Weapon` vs `Scourges with Heavy Weapons`）靠中文名接上。
   只认一对一，且不许碰已被英文名认领的行。
3. **新增覆盖对账命令** `python -m db_compile zh-coverage [--json 路径]`：
   把 units 全表**无遗漏**归进 5 类，各类计数之和恒等于 units 行数。

## 补不到的名单

**② 源里技能为空（16 个）**——已回黑图 **live 接口逐个复核**，`能力` 字段返回 `[]`，
不是缓存过期、不是抓取失败，重抓多少次都一样。这些单位黑图作者只填了属性/武器/
编制，没填技能正文：

托尔连长、西多尼亚哨兵、大头堡、瘟疫散播者、混沌复仇女神型巡游骑士、阿加通连长、
幽魂泰坦、火眼神射手（神射手小队）、舷炮战斗服（炮击战斗服小队）、
**危机火刃战斗服小队**、危机星镰战斗服小队、危机日铸战斗服小队、
克鲁特远猎者小队、克鲁特猎犬队、克鲁特猿兽骑兵小队、铁父费罗斯

> 这 16 个的 detail 里另有一个 `skill` 字段装着核心技能名（深入打击 / 领袖 /
> 不知疼痛 5 等），但那是**核心规则关键词**不是该兵牌的技能正文，与英文侧
> `abilities` 表里的具名技能（Fireknife、Weapon Support System）不是同一批东西，
> 拿它冒充技能正文就是造数，故不用。

**③ 源里有条目但无正文（2 个）**：天命者乌萨尔（Ûthar the Destined）、
战群统领（Kâhl），均属沃坦联盟。list 里有条目，detail 接口对英文名、去重音英文名、
中文名**七种写法全部**返回空——源侧没写。

**④ 源里有条目却没入库（1 个）**：地狱剥皮机（`Hellflayers` 000001144）。
黑图的 `Hellflayer` 已被库内同名单位 000004101 按英文名认领，中文名桥按纪律
不去碰已认领的行。两张兵牌是不是同一张需要人工裁定，留待后续。

**⑤ 源里根本没有（583 个）**：黑图 40K 库共 1168 条，其中 96 条是**没有英文名的
【传奇】条目**（太空野狼 legends 等），detail 接口拿中文名也取不到。库内 1715 行
本就多于源侧条目数，这个缺口是源的边界，不是抓取问题。

## 页面行为

`web_api/entity_card._abilities` 的既有规则：中文层条数 ≥ 英文表条数才用中文，
否则整块用英文表（完整权威源）。所以上述补不到的单位**逐字退回英文**，
页面上不会出现半中半英拼接，更不会出现没有出处的中文。

浏览器目检（2026-07-27）：危机火刃战斗服小队页面单位名/武器/装备/编制全中文，
技能区两条 `Fireknife` / `Weapon Support System` 为英文原文——这是正确行为。

## 顺带修掉的一个真 bug

刷新缓存后 `test_current_units_fully_localized` 转红，追下去发现
`db_compile/zh_weapons.py` 的数值指纹里，库内射程写 `Melee`、黑图写 `近战`，
两个写法从没归一 → **近战武器的 Pass A 指纹配对全盘失效**，一直只靠
「两边各只剩一把」的 Pass B 兜底。一个单位有两把以上近战武器时整组留英文
（地狱之末 3 把近战全是英文）。归一后指纹配对 4085 → **5341**，现役武器
中文覆盖 4718/4721 → **4721/4721**。

> 这个 bug 之所以躺了这么久没人发现：Pass B 恰好覆盖了「一把近战武器」这个
> 绝大多数情况，指标看起来一直很健康。是缓存刷新让某个单位多了一把近战武器，
> 才把它顶出水面。

毁灭者骑士的 `Darkflame lance` / `Terrorpulse missiles` 另走人工译名层：
黑图新版把 A 从 `2D6` 改成 `D6+6`，与库内英文权威不一致，指纹拒绝配对是**对的**
——只补名字，数值一律以库内英文为准。
