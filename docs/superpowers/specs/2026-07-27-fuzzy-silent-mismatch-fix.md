# 模糊匹配静默命中不相干单位：分布实测与修复（2026-07-27）

## 0. 病灶

```
entity_resolver("Flamestorm Drake")
  → canonical_id=000000918, name_en="Firestorm Redoubt", confidence="fuzzy"
get_entity("Flamestorm Drake")
  → found=True，直接返回 Firestorm Redoubt 的完整实体页
```

`Flamestorm Drake` 是个**不存在的名字**。系统没说「查不到」，而是用
`difflib.get_close_matches(cutoff=FUZZY_CUTOFF)` 换回了另一个真实单位的完整兵牌。

与前几轮修过的三种错法相比，这一种更危险：

| 缺陷 | 破绽在哪一层 |
|---|---|
| #109 查不到 → 编否定性断言 | 工具空返回，`_EMPTY_CHECKS` / `_fallback` 能接住 |
| #118 同名跨阵营不消歧 | 给的仍是同名单位里的一个，数值口径可对账 |
| #63 有歧义 → 不降级也不作答 | 0 检索源、答非所问，judge 一眼看穿 |
| **本轮：查错了** | **每一层都是成功路径**——found=True、数据真实、渲染正常 |

只有懂 40K 的人才看得出这张兵牌根本不是他问的东西。

## 1. 先量分布，再定判据

**不凭感觉调 cutoff。** 三类样本，共 2590 条查询，全部离线跑真解析器
（`wiki/terms.json` + `app.py` + `db/wh40k.sqlite`，池子 en=1319 / zh=1178）：

| 样本类 | n | 构造方法 | 判定 |
|---|---|---|---|
| **typo**（真纠错） | 1427 | 对库内真实名字做 5 类人类拼错扰动（删/换位/替换/去连字符/单复数），扰动串本身不得是库内已有名字 | 解析回**原** cid = 真纠错 |
| **abbrev**（简称） | 748 | 真实名字的连续子串（去头衔前缀 / 去尾词），本身不是库内名字 | 解析回**原** cid = 正确 |
| **bogus**（造名） | 415 | A 单位首词 + B 单位尾词拼装（确认不在库内）+ 15 个手写 40K 味造名（含 `Flamestorm Drake`） | **任何**命中都是离谱命中 |

相似度用与 `get_close_matches` **完全同一算法同一方向**的
`SequenceMatcher.set_seq2(query); set_seq1(possibility); ratio()` 复算。

### 1.1 为什么「把 cutoff 调高」是错的

```
真纠错命中的 ratio：min 0.750  p25 0.857  median 0.917  max 0.989
造名命中的 ratio：  min 0.600  p25 0.647  median 0.688  max 0.846
```

两个区间**重叠**（0.750–0.846），不存在能同时保住真纠错、挡住造名的比例阈值。

更糟的是调高 cutoff 会让情况**变坏**——滤掉竞争命中，会把「多命中 → ambiguous
（**不给** canonical_id）」变成「单命中 → fuzzy（**给** canonical_id）」：

| cutoff | 造名被接受（给出 id） | 造名判 none |
|---|---|---|
| 0.60（原值） | 56 | 23 |
| 0.75 | **79** | 309 |

「把门槛提高反而放进来更多」——这是本轮最反直觉的一条数据。

### 1.2 换成绝对字符编辑距离

ratio 是**比例**，名字越长越容易达标（`Flamestorm Drake` → `Firestorm Redoubt`
差 10 个字符仍有 0.606）。人类拼错只会差一两个字符，换成另一个名字则整词皆非：

```
真纠错到原单位的距离：en n=1092 max=2  /  zh n=335 max=2
造名到最近命中的距离：en p25=5 median=6 p95=10 max=16
```

两类之间有一段宽阔的空隙（真纠错 max 2 vs 造名 p25 5）。取 `FUZZY_MAX_EDITS = 2`。

### 1.3 只有编辑距离会误伤「用户打简称」——而且正好打在 #63 上

`坦克指挥官` 是 `黎曼鲁斯坦克指挥官` 的子串，编辑距离却有 **4**。一刀切会把两个正主
全滤掉、只留下距离 2 的 `远见指挥官`，于是 #63 从 ambiguous（三候选、正主在内）
翻成 **fuzzy 报 Commander Farsight**——比原缺陷更糟。

故加一条**单向**豁免：查询串是命中名的连续子串 ⇒ 按简称放行。
单向也是数据选的——反向（命中名是查询串的子串）等于放行「真名 + 自造修饰词」：

| 判据 | typo 单命中回原单位 | typo 误配 | abbrev 落空 | abbrev 误配 | **造名给出 id** | **造名判 none** |
|---|---|---|---|---|---|---|
| 仅 cutoff 0.6（改动前） | 490 | 0 | 17 | 102 | **57** | 23 |
| dist ≤ 2 | 1375 | 0 | 404 | 26 | 3 | 412 |
| dist ≤ 2 **或 简称子串**（采用） | 1368 | 0 | 61 | 58 | **3** | **412** |
| dist ≤ 2 或 双向子串 | 1326 | 0 | 61 | 58 | 45 | 370 |

采用的判据在**每一个轴上都不劣于**改动前：造名给出 id 57 → 3、真纠错单命中
490 → 1368（滤掉竞争杂项后正主独占）、简称误配 102 → 58，且 typo 误配始终为 0。

残留的 3 条造名（`KNIGHT SPINNER`→`NIGHT SPINNER` 差 1 个字母、`烈焰风暴巨龙`→
`烈焰风暴` 差 2 字、`血脊守望者`→`禁军守望者` 差 2 字）本就是该纠错的边界情形，
不是「离谱命中」；它们走**声明式** fuzzy 通道（见 §2.2），不会冒充成答案。

## 2. 修法（分布量出来之后才定的，两者结合）

### 2.1 解析器：低质量命中改判为「查不到 + 猜测」

`db_compile/entity_resolver.py`：`FUZZY_CUTOFF=0.6` 保留为**候选池粗筛**不动，
在其后加正交的第二判据；一个候选都过不了闸时返回
`confidence="none"` + 新字段 `suggestions`（**不是** `candidates`——后者是
「确实指向库内实体、可原样回填重查」的候选，前者只是「你要找的会不会是这个」）。

### 2.2 工具边界：把「猜测」两个字说死

`agent/tools.py`：

- `entity_resolver` / `get_entity` / `get_datasheet` / `calc_points` 四个工具
  透出 `suggestions`，并挂 `_RESOLVER_NEAR_MISS_NOTE`：必须先说库里没有、
  提到近似名必须标注为猜测、**禁止**拿它当用户所问的单位介绍数值。
- 被接受的 fuzzy 命中（拼错/简称）挂 `_FUZZY_DECLARE_NOTE`：**必须声明这是模糊匹配**。
  不声明的话，模糊命中拿回来的实体页与精确命中**长得完全一样**。
- `agent/llm_client.py` 系统提示词加一条铁律（与 #109 的「查不到 ≠ 不存在」并列）。

### 2.3 `_EMPTY_CHECKS`：两个工具放行，第三个**故意不放行**

`agent/loop.py` 中 `entity_resolver` / `get_entity` 带 `suggestions` 时判**非空**
（不降级，让模型据此如实作答，同 #118 的追加式补报做法）。

而 `get_datasheet` **故意不看** `suggestions`——这条是实测拍板的，不是设计出来的：

> 第一版把 `get_datasheet` 一并放行，基准 **#4（XV107 燃雨战斗服）与
> #62（重武器小队）当场 ✅ → ❌**。两者都是**真实存在**的单位，只是名字不在结构库
> 索引里，答案本来靠经典链从 PDF 语料捞回来（#62 正是 `loop.py` 注释里点名的
> 「俗名/集合名」回归 7 题防线）。

**结构库 ≠ 全部语料**，所以「结构库里没有这个名字」不足以支撑作答，必须让它去查语料；
而 `entity_resolver` 是纯「名字 → id」映射工具，「解析不到 + 只有几个像的」本身
就是它被问到的那个问题的实质答案。两者不可混为一谈。

## 5. 教训

1. **「把阈值调严」可能让漏网的更多**：滤掉竞争命中会把「多命中不给 id」变成
   「单命中给 id」。改判据前先把**判据变化后的路由分支**也一起量，别只量命中率。
2. **比例相似度对长名字太宽容**：`Flamestorm Drake` → `Firestorm Redoubt` 差 10 个
   字符仍有 0.606。要区分「拼错」与「另一个名字」，用**绝对**编辑距离而非比例。
3. **样本类别漏一类，就会打在锚点上**：第一版只造了 typo 与 bogus 两类，
   漏掉「用户打简称」，判据当场把 #63 的正主全滤掉。**先想清楚真实查询有几种形态**。
4. **同一个信号在不同工具上的语义不同**：`suggestions` 对纯映射工具
   （entity_resolver）是实质答案，对数据查表工具（get_datasheet）只是「结构库没有」，
   而结构库 ≠ 全部语料。一刀切放行当场打掉两道靠语料兜底的题。
5. **判基准回归必须先量波动带**：同代码连跑两次就有 4 题翻转，
   单看一轮的 ❌ 会把噪声当回归、也会把回归当噪声。
